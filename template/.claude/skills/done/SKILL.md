# done (세션 시작·마무리)

CLAUDE.md에 정의된 기록 체계(`_docs/WORK_LOG.md`, `_docs/log/YYYY-MM-DD.md`, `_docs/log/ACTIVE.md`)를 일관되게 유지하기 위한 의례적 스킬. **이 프로젝트 폴더 안에서만 동작**한다.

## 발동 시점

| 시점 | 모드 | 핵심 행동 |
|------|------|----------|
| 세션 시작 | `start` | 날짜 롤오버 체크 → 월간 아카이브 필요 시 수행 → 오늘 일별 로그 파일 준비(있으면 읽기, 없으면 보류) → ACTIVE 현황 사용자에게 브리핑 |
| 세션 종료 | `wrapup` | 이번 세션에서 한 작업을 분류·요약 → 오늘 일별 로그에 추가(파일 없으면 생성) → ACTIVE 상태 전이 |

호출 시 `args` 없이 사용된다. 모드 판정은 대화 맥락으로:
- 사용자 메시지에 "세션 마무리", "오늘 작업 기록", "wrapup", "끝" 류 단어 → **wrapup**
- 사용자 메시지에 "세션 시작", "오늘 뭐 해야", "ACTIVE 브리핑", "현황" 류 단어, 또는 대화가 비어 있고 사용자가 바로 호출 → **start**
- 애매하면 사용자에게 1줄로 물어본다 (AskUserQuestion 금지 — 단순 텍스트로)

## 경로·규칙

- **인덱스·규칙 정의**: `_docs/WORK_LOG.md` — 일별 로그 템플릿·롤오버 규칙·카테고리 목록 원전
- **일별 로그**: `_docs/log/YYYY-MM-DD.md` — 오늘 작업 누적
- **진행중·예정**: `_docs/log/ACTIVE.md` — 표 형식 (상태 / 일정 / 카테고리 / 내용)
- **월간 아카이브**: `_docs/log/YYYY-MM.md` — 월이 바뀌면 지난달 일별 파일들을 병합한 단일 파일

상태 이모지: `📝 진행중` · `🔧 검토대기` · `✅ 완료` · `⏸ 보류` · `🔜 예정`

카테고리 (`WORK_LOG.md` 정의): `리서치`·`문헌조사`·`데이터분석`·`행정`·`대외활동`·`기획`·`제안서`·`자동화`·`개발`·`개인` 등

## start 모드 절차

1. **오늘 날짜 확인** — 환경 변수 또는 사용자 메시지에서 (Today: YYYY-MM-DD). 요일도 같이.
2. **월간 롤오버 체크**:
   - `_docs/log/` 디렉터리 listing
   - 지난달(또는 그 이전) 날짜의 일별 파일(`YYYY-MM-DD.md`)이 남아 있는데 동일 월의 월간 파일(`YYYY-MM.md`)이 없거나 해당 일자 섹션이 없으면 → **병합 후보**로 사용자에게 보고하고 승인받아 진행
   - 병합 규칙: 일별 파일의 내용을 월간 파일에 `## YYYY-MM-DD (요일)` 섹션으로 추가, 본문은 간결 요약(긴 sub-bullet은 1～2줄로 압축). 병합 끝나면 일별 파일 삭제
   - 이번 달 안의 일별 파일은 건드리지 않는다
3. **오늘 일별 로그 준비**:
   - `_docs/log/YYYY-MM-DD.md` 존재 → Read하여 이미 기록된 항목 확인 (브리핑에 포함)
   - 없으면 → 아직 생성하지 않는다 (작업이 없을 수도 있으므로 wrapup에서 생성)
4. **ACTIVE 브리핑** — `_docs/log/ACTIVE.md` 읽어서 사용자에게 표 형식 그대로 또는 요약 1～2줄로 제시. 상태별로 묶어도 좋음.
5. **결과 보고** (텍스트, 5～10줄):
   - 오늘 날짜·요일
   - 월간 롤오버 수행 여부 (한 줄)
   - 오늘 이미 기록된 항목 (있다면)
   - 진행중·검토대기 항목 요약 (특히 오늘·이번주 일정)

## wrapup 모드 절차

1. **오늘 날짜 확인** (start와 동일)
2. **세션 작업 인벤토리** — 이번 대화에서 수행한 작업을 머릿속에서 분류:
   - 어떤 폴더·프로젝트에 무엇을 했는가
   - 카테고리 매핑 (`리서치`/`행정`/`개발`/...)
   - 산출물 경로·핵심 메모
3. **일별 로그 갱신**:
   - `_docs/log/YYYY-MM-DD.md` 없으면 → WORK_LOG.md의 일별 로그 템플릿대로 새로 생성
   - 있으면 → 기존 항목 끝에 새 작업을 `- **[카테고리]** 제목 — 상세` 형식으로 **추가**(덮어쓰기 금지). 같은 프로젝트의 후속 작업이면 같은 항목의 sub-bullet 또는 별도 항목 어느 쪽이 더 명확한지 판단해 선택
   - `## 메모` 섹션에 다음 세션이 알아야 할 후속 사항·특이점 추가
4. **ACTIVE.md 상태 전이**:
   - 진행 상황 갱신: 상태 코드 변경 (`📝 진행중` → `🔧 검토대기` 등), 내용에 최신 상황 1～2줄 추가
   - 완료된 항목 제거 (단, `## 완료` 섹션이 있으면 그쪽으로 이동도 가능)
   - 신규 진행중·예정 항목 추가
   - 표 칼럼 순서 유지: `상태 | 일정 | 카테고리 | 내용`
5. **프로젝트 폴더 _STATUS.md 점검** (선택):
   - 이번 세션에서 작업한 프로젝트 폴더(`YY.MM.DD. 카테고리. 제목/`)에 `_STATUS.md`가 있는지 확인
   - 있으면 — 이미 세션 중에 갱신했는지 확인. 미갱신이면 사용자에게 보고 후 갱신
   - 없는데 만들 만한 작업이었다면 — 사용자에게 신설 의향 물어보기
6. **결과 보고** (텍스트, 5～10줄):
   - 일별 로그에 추가한 항목 (제목만)
   - ACTIVE 상태 전이 (어느 항목이 어떻게 바뀌었는지)
   - 다음 세션에서 챙길 후속 사항 (있다면)

## 카테고리 매핑 가이드

| 단서 | 카테고리 |
|------|----------|
| 검색·웹 리서치·자료 수집 | 리서치 |
| 논문·문헌·해외 사례·정책 비교 | 문헌조사 |
| 데이터 추출·분석·차트·통계 | 데이터분석 |
| 보고서 제출·계약·정산·결재 문서 | 행정 |
| 강연·발표·자문·외부 회의 | 대외활동 |
| 사업계획·아이디어 정리 | 기획 |
| 제안서·공모 응모 | 제안서 |
| 스크립트·스킬·반복 작업 자동화 | 자동화 또는 개발 |
| 건강검진·연차·세금 | 개인 |

여러 카테고리에 걸치면 가장 비중 큰 것 하나만 표기. 부속 작업은 sub-bullet에서 자연스럽게 드러나도록.

## 일별 로그 항목 작성 원칙

- 첫 줄: `- **[카테고리]** 짧은 제목 — 위치(경로) + 한 줄 요약`
- sub-bullet: 의사결정·핵심 수치·산출물 경로·시행착오 — 다음에 다시 읽을 때 맥락 복원할 수 있게
- ★ 표시: 특히 중요한 결정·발견
- 코드 경로·명령은 백틱
- 너무 길어지면 별도 문서로 분리하고 링크만 일별 로그에 남긴다

## 월간 아카이브 작성 원칙

- 일별 파일 본문을 그대로 옮기지 않는다 — 1～3줄로 압축. sub-bullet은 핵심만 남기고 정리
- 동일 프로젝트의 여러 날 작업은 시간 순서를 유지하되, 메인 결정·완료 시점 위주로 요약
- 메모 섹션의 일회성 메모는 생략, 후속 영향이 있는 메모만 보존

## 주의사항

- **이 스킬은 작업 자체를 수행하지 않는다.** 일별 로그·ACTIVE 등 *기록 체계*만 다룬다. 작업 수행 중에는 호출 금지
- 일별 로그·ACTIVE는 사용자이 직접 읽는 파일 — 정확성 우선, 길이는 최소화
- 월간 롤오버 같은 파괴적 작업(일별 파일 삭제)은 **반드시 사용자 승인 후** 수행
- 의심스러우면 작업하지 말고 사용자에게 묻는다
